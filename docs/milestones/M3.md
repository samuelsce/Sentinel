# M3 — ingestão e SDK

Entrega implementada na branch `feat/m3-ingestion-sdk`, a partir da M2 integrada à main. Publicação por PR, sem merge automático. Data de validação: 8 de outubro de 2026. Execução e contratos em [INGESTION.md](../INGESTION.md).

## Resultado demonstrável

Uma aplicação HTTP própria decide login/autorização, emite eventos com o SDK Node.js e os persiste pela API autenticada. Cada evento novo cria um job durável na mesma transação. Reenvio idêntico mantém contagens e a chave/timestamp originais; conflito de conteúdo reverte o lote. Quotas são persistentes por projeto, compartilhadas entre chaves, e revogação é revalidada com lock transacional.

A demo de 15 eventos funciona com a API indisponível e torna perdas observáveis. O worker permanece idle; não há alertas, consultas de investigação ou dashboard nesta etapa.

Timeout é exercitado contra servidor HTTP real que não responde. Teste da demo com transporte indisponível preserva logins e autorização, contabilizando 15 perdas de confirmação.

## Aceite e limites

Os critérios funcionais da M3 foram atendidos. Não foram medidos os objetivos de p95/carga sustentada da M6. Os contadores do SDK são locais e voláteis; crash, overflow, rejeição ou falta de confirmação podem resultar em perda observável. A ingestão tem teto de backlog, mas retenção ainda está pendente. A demo é exclusivamente local, com sessões em memória e sem banco próprio persistente. Não foi feita alteração de design nesta etapa; somente textos do frontend foram atualizados para representar o estado implementado.
